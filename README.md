# 📚 数据库学习乐园（Database Learning Playground）

一个帮学生理解"**什么是数据库**"的教学平台。**全部数据以"文件"形式保存在你的 GitHub 仓库里**——不需要注册任何外部数据库服务（无需 Supabase）。

- 学生打开网页 → **注册 / 登录**（邮箱 + 密码）
- 登录后：**每人一个数据文件**（如 `data/wangxiaoming_stu_com.json`，按邮箱自动命名），里面是自己的档案和成绩
- 通过查看"表"、写简化版 SQL、修改资料、登记成绩，直观感受"数据是怎么被存储和操作的"

> 🎯 与学生讲解时可以这样说：
> "你们的账号和成绩都保存在 GitHub 仓库里，每个人一个文件。数据库，就是这些被管理的文件；SQL，就是查询它们的方法。"

## 📁 文件说明

| 文件 | 作用 |
|---|---|
| `index.html` | 学生使用界面（登录/注册 + 表浏览 + SQL 编辑器 + 我的资料 + 登记成绩 + 生成专属网页） |
| `style.css` | 界面样式 |

## 🚀 部署步骤（只需 GitHub，约 10 分钟）

### 第 1 步：创建 GitHub 仓库
1. 登录 GitHub，新建一个仓库（Repository），名字随意，如 `database-playground`
2. 建议选 **Public**（这样生成的专属网页可以直接访问；选 Private 也可以，但专属网页链接仅你自己可看）

### 第 2 步：生成令牌（Token）
1. 右上角头像 → **Settings** → 最下方 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
2. 填写：
   - **Token name**：随意，如 `class-token`
   - **Repository access**：勾选 **Only select repositories**，选你的仓库
   - **Permissions → Contents**：改为 **Read and write**
3. 点 **Generate token** → **立刻复制**生成的令牌（形如 `github_pat_...`，只显示一次！）

### 第 3 步：填写 `github-config.js`
用记事本打开 `github-config.js`，填入三个值：

```js
const GITHUB_OWNER = "你的GitHub用户名";
const GITHUB_REPO = "database-playground";
const GITHUB_TOKEN = "github_pat_你的令牌";
```

### 第 4 步：上传所有文件到仓库
把本文件夹里的**全部内容**（`index.html`、`style.css`、`app.js`、`github-config.js`、`data/` 文件夹）上传到仓库根目录。上传方式二选一：
- 网页上传：仓库页面 → **Add file → Upload files**，把文件拖进去提交
- 或使用 GitHub Desktop / Git 命令行推送

### 第 5 步：开启 GitHub Pages
1. 仓库 → **Settings** → 左侧 **Pages**
2. **Branch** 选 `main`（或 `master`），文件夹选 `/ (root)` → **Save**
3. 等 1~2 分钟，页面顶部出现网址：`https://你的用户名.github.io/仓库名/`

### 第 6 步：把网址发给学生
- 学生打开网址后，用**自己的邮箱 + 密码**注册即可，注册成功后自动进入系统
- 每人一个数据文件，文件名按注册邮箱自动生成（邮箱中的 `@`、`.` 会变成下划线，如 `abc@stu.com` → `abc_stu_com.json`）

## ✅ 部署后自测清单（上课前花 3 分钟）

打开你部署好的网址，按顺序检查：

- [ ] 打开显示**登录界面**（不是直接进入）
- [ ] 点「注册」→ 用你自己的邮箱 + 密码注册 → 进入主界面
- [ ] 右上角显示你的邮箱和名字
- [ ] 左侧「数据库中的表」显示：students（1 行）/ courses（5 行）/ scores（0 行）
- [ ] 点「students」→ SQL 编辑器自动填入 → 点「▶ 执行」→ 显示你这一行档案
- [ ] 点示例「成绩排序 ORDER BY」→ 显示自己的成绩从高到低
- [ ] 「📝 我的资料」填姓名、改班级 → 显示「资料已保存」
- [ ] 「＋ 登记成绩」选课程填分数 → 成绩表多一行 → 刷新页面后**数据还在**
- [ ] 「🌟 制作我的专属网页」输入名字 → 出现网址，1~2 分钟后打开能看
- [ ] 点「退出登录」→ 回登录界面；重新登录数据还在
- [ ] 再注册**另一个邮箱**登录 → 看到的是**另一个人的数据**

> ⚠️ 常见问题：
> - 打开显示「连接失败 / 尚未配置」→ `github-config.js` 没填对或没重新上传
> - 注册提示「该邮箱已注册」→ 之前注册过，直接点「登录」

## 🎓 学生能做什么？

- **注册 / 登录**：邮箱 + 密码；刷新页面自动保持登录
- **数据文件**：登录后只能看到、操作**自己的数据文件**（档案 + 成绩）；课程表是共享的
- **写简化 SQL**：编辑器支持 `SELECT / WHERE / ORDER BY / LIMIT`，以及 `COUNT / AVG / MAX / MIN` 聚合，执行后看到真实结果（数据来自自己的文件）
- **改资料 / 登记成绩**：真实写入自己的数据文件，刷新后还在
- **🌟 制作专属网页**：输入名字，自动生成一个属于自己的网页（含自己的成绩），得到可分享的网址
- **防破坏**：本环境只支持 `SELECT` 查询（写操作通过表单进行），不会破坏数据

### 教学建议（10 个内置示例由浅入深）

1. 让学生注册登录（任意邮箱 + 密码），体会"数据认识我"
2. 点左侧表名，看 students（自己的档案）/ courses（共享）/ scores（自己的成绩）
3. 示例 1~2：`SELECT *` 与选列
4. 示例 3、10：`WHERE` 条件筛选
5. 示例 4~5：`ORDER BY` 排序 + `LIMIT` 取前几行
6. 示例 6~7：`COUNT / AVG / MAX` 统计
7. 示例 8：`LIKE` 模糊查询
8. 课堂任务 A：「📝 我的资料」填姓名、改班级，再执行 `SELECT * FROM students;` 验证改的是自己的
9. 课堂任务 B：「＋ 登记成绩」加一门成绩，刷新后还在——数据真实保存在云端仓库
10. 课堂任务 C（压轴）：执行 `SELECT course, score FROM scores ORDER BY score DESC;` →「🌟 制作我的专属网页」→ 把网址贴到班级群

## ⚠️ 老师必读（安全与限制）

本版本**优先简单、不追求安全**（您已确认"只是给学生玩一下"）。请务必提前向学生说明：

1. **令牌公开**：`github-config.js` 里的令牌会出现在网页源码中，任何拿到网页的人理论上都能读写仓库文件。请使用**只授权本项目仓库、Contents 读写**的 Fine-grained 令牌，并告诉学生"不要乱动别人的文件"。
2. **数据按"前端隔离"**：登录后网页只加载自己的文件，但技术上并没有强制权限——学生懂技术的话可以绕过。教学场景可接受。
3. **并发写入**：多个学生同时操作自己的文件互不影响；但**同一个人**在两台设备同时打开时，后保存的会覆盖先保存的。提醒学生别同时开两个窗口。
4. **重置数据**：想恢复初始状态，把 `data/` 目录下生成的个人文件（按邮箱命名的 `.json`）和 `_accounts.json` 内容清回 `[]` 即可；`_courses.json` 保持不变。
5. **令牌过期**：Fine-grained 令牌默认 90 天到期，到期后在 GitHub 重新生成并更新 `github-config.js` 即可。
6. **GitHub 限制**：免费仓库无限空间，个人令牌 API 每小时 5000 次，一个班日常使用绰绰有余。

## ❓ 常见问题

| 问题 | 解决 |
|---|---|
| 打开显示「连接失败」 | 检查 `github-config.js` 三项是否填对、文件是否已上传仓库 |
| 注册提示「该邮箱已注册」 | 之前注册过，直接点「登录」；或删除 `data/_accounts.json` 中对应条目后重新注册 |
| 数据被改坏了 | 编辑 `data/` 下对应文件恢复；或删除该文件让学生重新注册 |
| 专属网页打不开 | GitHub Pages 部署需要 1~2 分钟，稍等刷新；确认仓库是 Public |
